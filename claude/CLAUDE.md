# Arbeitsweise

- Browser-Tests mit Playwright (MCP `playwright-server`). Für Lighthouse und Performance nutze `chrome-devtools`.
- Vor größeren Änderungen kurz den Plan nennen. Kleine Fixes direkt umsetzen.
- Keine Auto-Commits. Commit-Messages auf Deutsch oder im Conventional-Commit-Stil, je nachdem, was im Repo üblich ist.
- **Vor `git push`, Deployments und Datenbank-Migrationen immer fragen.**
- Chirurgisch ändern: nur anfassen, was die Aufgabe braucht. Nachbarcode, Kommentare und Formatierung nicht „mitverbessern“, bestehenden Stil übernehmen. Fremden toten Code nur erwähnen, nicht löschen – aufräumen nur, was die eigene Änderung ungenutzt gemacht hat.
